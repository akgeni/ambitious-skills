# Ambition Depth

Push tasks to the rigor, tools, and standards used by top specialists in the field.

## When to Use

- User requests analytical, technical, mathematical, or scientific problem-solving.
- Work risks defaulting to shallow summaries, generic markdown tables, or surface heuristics.
- User is optimizing performance (latency, accuracy, throughput) or investigating root causes (churn, regressions).

## Principles

- **Insist on Professional Instruments:** Reject hand-waving and formatted markdown tables when statistical models, databases, or executable scripts are appropriate.
- **Set Unreasonable Benchmarks:** Reframe conventional targets into aggressive goals (e.g., 200ms latency instead of 5s) and treat them as solvable engineering challenges.
- **Start from Raw Material:** Work directly with raw logs, unaggregated data, or primary source code rather than digested summaries.
- **Enforce Outside Validation:** Never let a model grade its own work. Require executable tests, external scripts, benchmark suites, or compiler outputs.

## Workflow

1. **Conduct the Depth Audit:**
   - Identify what an industry-leading expert would do that was not explicitly requested.
   - Identify the rawest input data required.
   - Select the definitive domain tools (e.g., statistical frameworks, formal verification, profilers).
   - Define an objective external test of correctness.

2. **Adversarial Assumption Testing:**
   - Treat current organizational assumptions as hypotheses to test against raw data.
   - Run counter-factuals or simulations to discover blind spots and early predictive signals.

3. **Execute and Verify:**
   - Run the professional tools and models.
   - Validate outputs against external verification criteria before finalizing.

## Gotchas

- Avoid "vocabulary switching" without method switching. Adopting expert jargon without running expert methods is not depth.
- Always provide reproducible validation criteria or executable code rather than subjective assurances.
